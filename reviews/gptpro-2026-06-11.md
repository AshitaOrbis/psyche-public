P0-1 — CAT reverse-scored items are not reverse-mapped before GRM scoring

Files / quoted lines

web/src/scoring/grm-engine.ts states that reverse scoring must be handled by response mapping:

“reverse scoring is metadata for response mapping (flipping the response before computing probabilities)”
“reverse is NOT used in the GRM probability computation itself.” 

grm-engine

But AdaptiveTestRunner only converts the clicked 1–5 value to a 0-indexed category:

const category = value - 1;
registerResponse(..., currentItem.item.id, category, ...) 

AdaptiveTestRunner

registerResponse stores that category unchanged:

const response: CATResponse = { itemId, category };
estimateTheta(administeredItems, newAdministered, ...)

The item banks do include reverse: true items with positive discriminations, for example CAT-N1-003 and CAT-HH1-003.

hexaco-grm-params

Scenario

A reverse-keyed anxiety item conceptually like “I rarely feel anxious” should lower anxiety theta when answered “Very Accurate.” This implementation treats the high category as high theta. Enough reverse-keyed items will bias theta, SE, item selection, and final percentiles in the wrong direction.

Fix

Flip categories before likelihood calculation:

TypeScript
const scoredCategory = item.reverse
  ? item.numCategories - 1 - category
  : category;

Do this inside registerResponse after item lookup and before storing/scoring, or normalize all responses before estimateTheta. Also add tests:

TypeScript
expect(estimateTheta([reverseItem], [{ itemId, category: 4 }]).theta)
  .toBeLessThan(estimateTheta([reverseItem], [{ itemId, category: 0 }]).theta);

Alternatively, encode reverse items with calibrated negative discrimination and transformed thresholds, but that conflicts with the current a > 0 interface contract.

P0-2 — Shipped CAT item banks contain placeholder item text, so adaptive scores are not psychometrically meaningful

Files / quoted lines

web/public/item-banks/big5-grm-params.json:

hexaco-grm-params

The controller has a warning-only validator, but it only checks whether all discrimination values are identical and explicitly says it does not check threshold diversity, discrimination range, cross-validation fit, or item content quality. 

cat-controller

 The adaptive runner loads the bank and accepts it directly:

fetch(itemBankUrl)
.then((data: GRMItem[]) => { setItemBank(data); ... }) 

AdaptiveTestRunner

Scenario

A user sees placeholder prompts such as [Anxiety item 1] and responds anyway, or the UI ships a CAT instrument whose displayed stimuli are not real items. No amount of GRM math can make the resulting theta estimates valid.

Fix

Block CAT instruments unless the item bank passes a hard validator. At minimum:

TypeScript
function validateCATBankOrThrow(bank: GRMItem[]) {
  for (const item of bank) {
    if (/^\[[^\]]+ item \d+\]$/.test(item.text.trim())) {
      throw new Error(`Placeholder CAT item text: ${item.id}`);
    }
    if (!Number.isFinite(item.discrimination) || item.discrimination <= 0) {
      throw new Error(`Invalid discrimination: ${item.id}`);
    }
    if (item.thresholds.length !== item.numCategories - 1) {
      throw new Error(`Threshold/category mismatch: ${item.id}`);
    }
    if (!item.thresholds.every(Number.isFinite)) {
      throw new Error(`Non-finite threshold: ${item.id}`);
    }
    for (let i = 1; i < item.thresholds.length; i++) {
      if (item.thresholds[i]! <= item.thresholds[i - 1]!) {
        throw new Error(`Unordered thresholds: ${item.id}`);
      }
    }
  }
}

Hide CAT from production tiers until real calibrated items and parameters are available.

P1-2 — README says sessions expire after 7 days, but the web store has no TTL or purge logic

Files / quoted lines

README:

“Sessions expire after 7 days.” 

README

Store persist config:

name: "psyche-store"
onRehydrateStorage: () => (state) => { if (state) autoScoreCompleted(); } 

store

There is no expiresAt, lastSavedAt, version, migrate, or rehydrate purge in the reviewed store.

Scenario

A user completes highly personal tests or open-ended prompts, closes the browser, and returns weeks later. The data will remain in localStorage until cleared by the user/browser or overwritten. That is a retention claim mismatch.

Fix

Add persisted metadata and purge on rehydrate:

TypeScript
persist(
  ...,
  {
    name: "psyche-store",
    version: 1,
    migrate: migratePsycheStore,
    partialize: (s) => ({ ...s, savedAt: Date.now() }),
    onRehydrateStorage: () => (state) => {
      if (!state) return;
      const savedAt = state.savedAt ?? 0;
      if (Date.now() - savedAt > 7 * 24 * 60 * 60 * 1000) {
        usePsycheStore.setState(initialState, true);
        return;
      }
      autoScoreCompleted();
    },
  }
)

Or remove the 7-day claim.

P1-5 — autoScoreCompleted can mint empty or corrupt results from malformed/imported sessions

Files / quoted lines

The store auto-scores any session whose count of unique response IDs is at least the instrument item count:

if (new Set(session.responses.map(r => r.itemId)).size >= instrument.items.length) {
newResults[id] = score(instrument, session); 

store

It does not require that the response IDs match the instrument’s actual item IDs.

Scenario

An imported JSON file contains 60 unique junk response IDs for ipip-neo-60. The store decides the instrument is complete, calls the scorer, and may store an empty or nonsensical result. Because results[id] then exists, later valid scoring is skipped.

Fix

Validate exact coverage:

TypeScript
const required = new Set(instrument.items.map((i) => i.id));
const answered = new Map(session.responses.map((r) => [r.itemId, r]));

const complete = [...required].every((id) => {
  const r = answered.get(id);
  return r && isValidResponseForItem(r.value, instrument.items.find(i => i.id === id)!);
});

Also reject “completed” scoring if result.scores.length === 0 for instruments that should produce scores.

P1-6 — Import validation is too shallow and can accept malformed scores/sessions or throw during import

Files / quoted lines

importData validates only top-level sessions and results object presence:

Invalid data: sessions and results must be objects 

store

Then it assumes every session has .responses.filter(...):

session.responses = session.responses.filter(r => { ... }) 

store

And assumes every result has .scores:

for (const score of result.scores) { ... } 

store

It clamps only normalized, not raw, theta, se, completedAt, response ranges, instrument IDs, timestamps, or array shapes.

Scenario

A malformed backup with responses: null throws an uncaught TypeError. A crafted backup with finite-but-out-of-range Likert values, bogus theta/se, huge timestamps, or mismatched instrument IDs can be imported and later rendered/scored.

Fix

Use a schema validator or explicit guards before merge. Reject or repair:

sessions[id].responses must be an array.

itemId must exist in the registered instrument.

response value must match item type/range.

timestamp, startedAt, completedAt must be finite plausible numbers.

scores must have finite raw, normalized, optional finite theta, positive finite se.

Import should fail atomically with a user-visible error.

Verdict

The privacy claim is honestly delivered by the reviewed client-side web-app code only if reworded away from literal “no IP.” The app code appears to keep test responses/results on-device and does not set cookies, use accounts, fingerprint, or call external APIs for the reviewed flows. The deployed-site claim should disclose ordinary Cloudflare request metadata and should not say sessions expire after 7 days until TTL logic exists.

The app is not scoring-release-ready. The CAT path has two P0 validity blockers: reverse-keyed items are scored in the wrong direction, and the shipped adaptive item banks contain placeholder prompts.

Three likely-missed findings

Security headers / CSP are not established in the reviewed files. Add Cloudflare Pages _headers with a strict CSP such as default-src 'self'; script-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'.

Open-ended prompts are highly identifying even without accounts. The instrument explicitly stores qualitative free text for export/LLM analysis. The UI should label that export as potentially identifying and strip timestamps by default. 

open-ended

NPM package drift can change psychometric item content/schema. The web app depends on external IPIP question packages via semver ranges; pin versions tightly and add snapshot tests for item IDs, keyed direction, scale/facet mapping, and response ranges.
