# Phase A #7 — cited-basis audit of Gate 3

**Date**: 2026-06-28
**Driver**: `drivers/analysis/gate3_cited_basis.py` (+ deterministic key regen via `gate3_prepare.py`)
**Outputs**: `reports/analysis/gate3_cited_basis.json`, `gate3_cited_basis_items.md` (per-item coding)
**Cost**: zero new model calls — codes the 64 already-stored Gemini `basis` rationales (`gate3_verdicts_g{0-3}.json`).

## Purpose
The v0.3 Gate-3 headline (blind persona recovery **0.93**) was caveated in Gate 3b: Gemini's stated bases "frequently cite the output echoing contract phrasing," so the recovery might be **surface/echo**, not behavioral adaptation. This audit quantifies that: it codes each recovery rationale as **behavioral** (abstract stance / reasoning / omission / strategy) vs **surface/echo** (verbatim phrase, quoted span, or a distinctive contract token a neutral paraphrase would strip), and reports recovery split by bucket. Per GPT Pro's triage rule, a behavior-heavy result points to **#2 (target-conditioned re-judging)** as the next expensive gate; a surface-heavy result makes **#1 (neutral-paraphrase recovery)** the required gate.

## Method & integrity
- Answer key (`/tmp/gate3_keys.json`, out of Gemini's reach) regenerated **deterministically** (`gate3_prepare.py`, SEED=20260617, frozen run inputs). The 64 prompt files regenerated byte-identically (`git status` clean → key derivation provably matches the original run).
- The audit driver **asserts reproduction** of the published `gate3_results.json` (recovery 0.93 n=128; cross-tab 45/16/1/2) before coding — so the basis→recovery join is the one Gemini actually judged.
- Coding = a **transparent keyword/regex rubric** (auditable, no LLM). **Limitation**: single automated coder, no human double-coding; bases are ≤18 words. Per-item coding emitted for review. One rubric bug fixed in development (possessive apostrophes in "P1's…P2's" spuriously matched the quoted-span pattern, over-flagging echo); after fix, all 21 echo rows verified to cite a genuine surface cue.

## Result (n=64 tasks, reproduction-verified)

| Bucket (cue the coder cited to recover persona) | n | % | recovery |
|---|---:|---:|---|
| **behavioral** (no surface cue) | 43 | 67.2% | 0.907 [0.827, 0.952] |
| **mixed** (behavioral + an echo cue) | 18 | 28.1% | 0.972 [0.858, 0.995] |
| **surface** (echo/token only) | 3 | 4.7% | 1.00 [0.61, 1.0] |
| unclear | 0 | 0.0% | — |

- **Explicit-echo-cue rate (any verbatim/quoted/token cue): 21/64 = 32.8%.** Pure-behavioral: **43/64 = 67.2%.** Pure-surface: only **4.7%**.
- Recovery is **high in both** buckets — echo-citing 0.976 vs non-echo 0.907 (CIs overlap) — i.e. recovery is **not driven by** echo; the 43 pure-behavioral tasks recover at **0.91** with no surface cue cited at all.
- The 33% echo tail is concentrated in distinctive contract tokens — `'next 30 seconds'`, `'24-hour holds'`, `'observable step'`, `'checkable language'`, `'Thursday'`, `'10 a.m.'` — plus explicit "exact/verbatim/mirrors/literal phrases" claims.

## Reading (triage)
**Behavior-leaning, not clean.** Two-thirds of blind recoveries cite an abstract behavioral/reasoning/omission/strategy axis with no surface cue, and those recover at 0.91 — strong evidence the bulk of the 93% rests on **behavioral discrimination, not phrase-spotting** (only 4.7% pure-surface). This is **more reassuring for generation** than Gate 3b's caveat implied.

**But two things keep #1 alive as the confirmatory arbiter, not skippable:**
1. A non-trivial **32.8%** of recoveries lean on at least one verbatim/token cue a neutral paraphrase would strip.
2. "Cited a behavioral axis" ≠ "the output *enacts* the behavior." A basis saying "uses confidence levels" can reflect the output literally writing a contract-mandated `confidence: 70%` token (directive-following) rather than genuine adaptation. Only the **neutral-paraphrase recovery test (#1)** cleanly separates enactment from contract-paraphrase.

Net: the "Both, sequenced" path is now well-motivated (#2 in the Gemini-blocked window, #1 at quota reset).
