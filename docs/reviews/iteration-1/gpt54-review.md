## Findings

### [CRITICAL]: Sensitive Clinical Data Exposed as Public Static Assets
**File:** web/public/seed-data.json, web/public/profiles/owner-v2.json (name redacted), web/public/profiles/manifest.json
**Category:** security
**Confidence:** CERTAIN
**Description:** `seed-data.json` contains PHQ-9/GAD-7 item responses, free-text self-disclosure, and clinical scores. `profiles/owner-v2.json (name redacted)` and `manifest.json` publish identified profile data. These are served as static files accessible to anyone, indexable by search engines, and cached by CDNs/Wayback Machine. The Zustand store fetches `seed-data.json` on every page load (`store.ts:onRehydrateStorage`).
**Impact:** Direct privacy breach. Sensitive clinical data (depression/anxiety scores, personal narrative responses) publicly accessible. Worse than localStorage exposure because it's server-hosted and persistent.
**Suggested Fix:** Remove files immediately. Add CI rule blocking PHQ/GAD payloads in `public/`. Purge CDN caches. If seed data is needed for development, use a `.gitignore`d local file or environment-gated fetch.

### [CRITICAL]: Indefinite Session Retention Violates Stated 7-Day TTL
**File:** api/src/routes/psyche.ts (cleanup endpoint, ~line 440-450)
**Category:** security
**Confidence:** CERTAIN
**Description:** The cleanup logic only deletes `active` and `withdrawn` sessions past their `expires_at`. Completed sessions persist indefinitely in the database, even though the client-side TTL is 7 days. Sessions with consent level 1 (no research opt-in) should be deleted after expiry per the privacy design.
**Impact:** Violates the 7-day retention promise made to users. Potential GDPR/privacy regulation non-compliance for sessions containing psychological assessment data.
**Suggested Fix:** Extend cleanup to also delete completed non-research sessions (consent_given < 2) past their `expires_at`. Research-opted sessions (consent_given >= 2) can retain per research consent terms.

### [CRITICAL]: Stored XSS via Import + recover.html
**File:** web/src/state/store.ts:1204 (importData), web/public/recover.html:49,58,61
**Category:** security
**Confidence:** CERTAIN
**Description:** `importData()` does `JSON.parse(json)` without validation and merges directly into state/localStorage. `recover.html` then writes localStorage-derived values into `innerHTML` at lines 49, 58, and 61. A crafted import file can inject script payloads that execute when `recover.html` is opened.
**Impact:** Attacker can execute arbitrary JavaScript in the app's origin context via a malicious import file. Could exfiltrate all localStorage data (assessment results, session IDs).
**Suggested Fix:** Remove `recover.html` or rewrite with `textContent` instead of `innerHTML`. Add schema validation to `importData()` (Zod or manual type checks) before merging into state.

### [HIGH]: CAT Item-Bank Schema Mismatch
**File:** web/src/scoring/grm-engine.ts:16-18, web/public/item-banks/big5-grm-params.json:3-4, web/src/scoring/cat-controller.ts:198
**Category:** scoring-correctness
**Confidence:** CERTAIN
**Description:** The GRM runtime expects `GRMItem.id` and `GRMItem.text`, but the shipped item bank JSON files use `itemId` and `itemText`. The `AdaptiveTestRunner.tsx` trusts the JSON as `GRMItem[]` without validation. `cat-controller.ts` looks items up by `i.id`, which would be `undefined` for the shipped data.
**Impact:** CAT adaptive testing is non-functional with the shipped item banks. Blank item text displayed, undefined item IDs break administered-item tracking, theta estimation based on wrong item lookups.
**Suggested Fix:** Either rename JSON fields to match the `GRMItem` interface, or add a mapping layer that transforms the loaded data. Add runtime schema validation when loading item banks.

### [HIGH]: CAT Banks Are Synthetic Placeholders with Unused Reverse Flags
**File:** analysis/scripts/generate_synthetic_banks.py:53, web/public/item-banks/hexaco-grm-params.json:37
**Category:** scoring-correctness
**Confidence:** CERTAIN
**Description:** The shipped item banks are synthetic placeholder data (generated by a Python script). Additionally, they carry `reverse` key flags that the CAT scoring path never applies -- `scoreLikert()` handles reversal for fixed-form instruments, but the CAT path in `grm-engine.ts` ignores the `reverse` field entirely.
**Impact:** Even if the schema mismatch is fixed, CAT results would be based on synthetic (non-validated) IRT parameters and would not reverse-score items correctly. Results would be psychometrically invalid.
**Suggested Fix:** Document CAT as experimental/non-production. Block CAT instruments from the production tier definitions until real item banks with validated parameters are available. Add reverse-scoring support to the GRM scoring path.

### [HIGH]: Standalone App Lacks Crisis Safety Interstitial for PHQ-9/GAD-7
**File:** web/src/instruments/phq9-gad7.ts:72, web/src/components/TestRunner.tsx:150, web/src/components/ResultsViewer.tsx:52
**Category:** crisis-safety
**Confidence:** CERTAIN
**Description:** The standalone Vite app's PHQ-9/GAD-7 flow only computes sums. There is no crisis-resources interstitial, no item-9 escalation check, and no persistent crisis footer. The `TestRunner.tsx` goes directly to a generic completion screen. This contradicts `docs/ETHICS-PROTOCOL.md:111` which specifies a crisis-resource interstitial and persistent footer link.
**Impact:** Users completing depression/anxiety screening in the standalone app receive no crisis intervention resources. The Next.js deployment (`tier-3-nextjs`) DOES have `CrisisResources.tsx` with both interstitial and footer variants, but the standalone app does not.
**Suggested Fix:** Port the `CrisisResources` component pattern from Next.js into the standalone app's `TestRunner.tsx` flow. Add crisis interstitial after PHQ-9/GAD-7 completion with hotline numbers. Add persistent footer during assessment phases.

### [HIGH]: API Uses Wildcard CORS + Session-UUID-Only Auth
**File:** api/src/routes/psyche.ts (types.ts:74 for CORS)
**Category:** security
**Confidence:** CERTAIN
**Description:** `Access-Control-Allow-Origin: *` allows any origin to call the API. Report generation requires only the session UUID (no user authentication, no token). Rate limiting is in-memory (ephemeral on Workers). Combined: if a session UUID leaks (browser history, referrer headers, shared URLs), anyone can view scores, generate reports, or withdraw consent.
**Impact:** UUID leak grants full session access. Weak cost control on paid LLM report generation (DeepInfra API calls). Any website can make cross-origin requests to the Psyche API.
**Suggested Fix:** Restrict CORS to `app.ashitaorbis.com` and `localhost` origins. Add `Referrer-Policy: no-referrer` to assess pages. Move rate limiting to durable storage (KV/D1). Consider session-scoped CSRF tokens for destructive operations.

### [MEDIUM]: Client Data Injected Into LLM Prompt Without Validation
**File:** api/src/routes/psyche.ts (buildReportPrompt / report generation)
**Category:** security
**Confidence:** HIGH
**Description:** `saveInterview()` stores raw free-text responses. The report generation concatenates these into the Kimi K2.5 system prompt without escaping or validation. Score objects from `saveScores()` are also included verbatim with no schema validation.
**Impact:** Prompt injection via interview responses (e.g., "Ignore previous instructions and..."). Manipulated score objects could produce misleading narrative reports.
**Suggested Fix:** Sanitize interview text (strip control characters, limit length). Validate score objects against expected schema before including in prompt. Consider separating user content from system instructions in the prompt structure.

### [MEDIUM]: XSS in recover.html via localStorage-Derived innerHTML
**File:** web/public/recover.html:49,58,61
**Category:** security
**Confidence:** CERTAIN
**Description:** `recover.html` reads localStorage values and writes them into the DOM using `innerHTML`. Since `importData()` can persist arbitrary JSON into localStorage without validation, this creates a stored XSS vector.
**Impact:** Any malicious content persisted via import or direct localStorage manipulation executes as HTML/JS when `recover.html` is loaded.
**Suggested Fix:** Replace all `innerHTML` usage with `textContent`. Or remove `recover.html` entirely if the export/import workflow handles recovery.

### [MEDIUM]: API Client Has No Timeouts or Content-Type Validation
**File:** tier-3-nextjs/src/lib/psyche/api.ts, tier-2-astro/src/lib/psyche/api.ts
**Category:** api-contract
**Confidence:** CERTAIN
**Description:** Neither API client sets a timeout on `fetch()` requests. Neither validates `Content-Type` headers on responses. Report generation can take 30+ seconds (LLM inference) with no user-visible progress or cancellation.
**Impact:** Users left waiting indefinitely on slow networks or server errors. Non-JSON responses (HTML error pages, Cloudflare challenge pages) parsed as JSON produce cryptic errors.
**Suggested Fix:** Add `AbortController` with timeout (30s for reports, 10s for other calls). Check `Content-Type: application/json` before calling `res.json()`. Show progress indicator for report generation.

### [MEDIUM]: Score Normalization Has No Bounds Validation
**File:** web/src/scoring/engine.ts:465-469
**Category:** scoring-correctness
**Confidence:** HIGH
**Description:** Normalized scores can exceed 0-100 range if imported data contains out-of-range values (response value > max or < min for the scale). Division by zero occurs if `max === min`. No clamping is performed.
**Impact:** Silently incorrect scores from malformed imports. Division by zero produces NaN/Infinity scores that propagate through results and into report generation.
**Suggested Fix:** Clamp normalized scores to [0, 100]. Guard against division by zero (`max === min` → normalized = 50 or 0). Validate imported response values against instrument bounds.

### [MEDIUM]: Response-Timing Race Conditions in TestRunner
**File:** web/src/components/TestRunner.tsx:51,70, web/src/components/AdaptiveTestRunner.tsx:102
**Category:** state-management
**Confidence:** HIGH
**Description:** `TestRunner.tsx` schedules blind delayed advances (setTimeout). Rapid double-clicks or keyboard input during the delay can skip items or register duplicate responses. `AdaptiveTestRunner.tsx` has no in-flight guard for `registerResponse`, and `cat-controller.ts` never deduplicates repeated CAT responses before incrementing counts.
**Impact:** Fixed-form can skip questions; CAT can distort theta/SE through duplicate response registration.
**Suggested Fix:** Add a `processing` flag that disables input during the advance delay. Deduplicate CAT responses by itemId before processing.

### [LOW]: Missing Registry Entries Fail Open Silently
**File:** web/src/instruments/tiers.ts:101, web/src/state/store.ts:185
**Category:** edge-case
**Confidence:** CERTAIN
**Description:** `getInstrumentsForTier()` removes replaced instruments without validating replacements exist in registry. The UI (`App.tsx`) silently filters unregistered IDs. `autoScoreCompleted` silently skips orphan sessions. `ResultsViewer` shows "Unknown instrument" with no user action path.
**Impact:** A misconfigured tier definition could silently drop instruments from the assessment without any error. Users complete fewer instruments than expected and receive partial results.
**Suggested Fix:** Add validation at startup: assert all instruments referenced by tier definitions are registered. Log warnings for orphan sessions.

---

### [LOW]: Reverse Scoring Formula Correct but No Input Clamping
**File:** web/src/scoring/engine.ts:85,102
**Category:** scoring-correctness
**Confidence:** CERTAIN
**Description:** The reverse formula `max + min - value` is mathematically correct for bounded Likert scales. However, imported values outside [min, max] are not clamped before reversal, which can produce reversed values outside the expected range.
**Impact:** Only affects malformed imports. Normal UI input is bounded by the response format definition.
**Suggested Fix:** Clamp values to [min, max] before scoring, or validate at import time.
